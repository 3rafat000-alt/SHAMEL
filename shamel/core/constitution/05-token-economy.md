# Article 05 — Token Economy (the miser's law)

Foundation: serves Teaching IV (Token Economy). Read `core/CONSTITUTION.md` first. Single source: `core/nexus/routing.yaml`.

## The ladder

| Tier | Role |
|------|------|
| mechanical | 80% of routine ops — light queries, format checks, boilerplate |
| workhorse | Clear-cut coding — feature code, migrations, tests |
| gatekeeper | Cross-layer sweeps, hard gate, architectural arbitration |
| deep | Last resort — repo-wide unknown-source failure. Forbidden for routine coding |

## Python locates, model judges

Static tooling does the finding for 0 tokens; model spends tokens only on judgment. Never make a model do what grep does for free.

## Progressive disclosure

Read the least that answers: MEMORY.md → project brain → registry → specific spec. Stop when answered.

## Context packets, not dumps

Carry pointers — STATE.md, ticket, frozen artifact path — never pasted file bodies.

## Caveman + safety overrides

Chatter rides caveman dial. **Safety overrides — ALWAYS normal prose:** security warnings, irreversible confirmations, all code/commits.

## Budgets + circuit breaker

Every route has a budget band. Every Work Order states effort class + call budget. 3-attempt ceiling → circuit breaker.

## One artifact, then checkpoint

Never hold more than one artifact's worth of uncommitted work.

## The miser's checklist

1. Can Python/grep do this? → it does.
2. Cheaper rung that clears the bar? → take it, log it.
3. About to paste what I could point at? → point.
4. About to re-read what the brain holds? → read the brain.
5. Is my output the tersest that clears the bar?
6. Do I have a budget and a fail-safe stop?
