## القسم 2 — النتائج (مرقّمة بالخطورة)

### 🔴 F-01 — CRITICAL — معيارا قبول متنافيان: «صفر ملفات sofi*» مقابل شحن `sofi_scan`/`sofi_verify`

- **الأطراف:** معيار FR-05 (§9): «`find ~/Desktop/SHAMEL -name 'sofi*' -type f` = 0» (بلا فلتر `-executable` وبلا استثناء `archive/`)، وG-03 (§3): نفس الفحص بـ `-executable` = 0 — **مقابل** FR-81 (سطر ~420): «الماسحات (feature_scan · **sofi_scan** · **sofi_verify** …) تعيش نسخة واحدة في `os/scanners/`» و§4.3 (سطر 146): `scanners/ # feature_scan · sofi_scan · verify`.
- **الدليل من الواقع:** `company/os/agents/ceo/sofi_scan.py` الحالي executable فعلاً (يلتقطه فحص G-03 أيضاً وليس FR-05 فقط).
- **الأثر:** حزمة القبول الميكانيكية fail-closed — جوهر الوثيقة — **غير قابلة للإرضاء كما كُتبت**: تمرير FR-81 يُفشل FR-05/G-03 حتمياً والعكس. المنفّذ الحرفي سيُسقط أحد المتطلبين بصمت.
- **مضاعف:** FR-20 يعرف نمط `-path ./archive -prune` ويستخدمه، بينما FR-05/G-03 بلا استثناء archive — أي أرشفة legacy تحت `archive/` تحوي ملف sofi* تُفشلهما أيضاً.
- **تناقض اسمي فرعي:** §4.3 يسمّي الماسح الثالث «verify» وFR-81 «sofi_verify».
- **الإصلاح:** إعادة تسمية الماسحات في FR-81 و§4.3 (`shamel_scan`/`shamel_verify` — اتساقاً مع روح FR-05 نفسه «حزمة إعادة التسمية الواحدة»)، أو تقييد فحص FR-05/G-03 صراحةً؛ + توحيد الاسم الثالث؛ + إضافة `-path ./archive -prune` للفحصين.

### 🔴 F-02 — CRITICAL — مصدران يدّعيان كلاهما «الوحيد» لنفس الحقل: route الوكيل (خرق نصي للمبدأ الحاكم 1)

- **الأطراف:** §4.3 (سطر 135): «الـ spec = **مصدر الحقيقة الوحيد** للوكيل»، وfrontmatter FR-02 يحمل `route: {tier, effort, caveman, budget}` — **مقابل** FR-60 (سطر 373): «`nexus/routing.yaml` هو **مصدر التوجيه الوحيد** … route لكل وكيل + مسارات مهام».
- **الأثر:** نفس الـ concern (route لكل agent-id) له مصدران حيّان كلاهما موصوف «الوحيد»، بلا علاقة توليد أو فحص parity معلنة بينهما — وهذا حرفياً نمط GAP-07 («تعريفان حيّان لنفس الـ ID») الذي بُنيت الوثيقة لقتله، وخرق مباشر للمبدأ الحاكم 1 «غير القابل للتفاوض». المفارقة: FR-03 حلّ المشكلة نفسها لمنح الويب (registry مصدر + إسقاط عند التوليد + فحص تطابق في معيار FR-03) — وroute تُرك بلا نظير.
- **نفس النمط الأخف:** `gate:` في frontmatter مقابل قوائم `agents:` لكل بوابة في gates.yaml — بلا فحص تطابق معلن.
- **الإصلاح (سطر واحد):** إعلان الاتجاه القانوني — إمّا «routes في routing.yaml تولَّد من frontmatter الـ specs بأمر `shamel agents build` وdoctor يفحص التطابق»، أو العكس (frontmatter مرآة مولّدة) — وذكر فحص parity الـ route (وgate) ضمن FR-34.
