### 🟠 HIGH

- الـ glob يشمل **MASTER-PLAN.md نفسه** (سطر 117 — نص ADR-006 يذكر `.shamel/` و`schemadb` بالضرورة لأنه يوثّق البدائل المرفوضة، وسطر 138 — أمر الفحص ذاته يحوي الأنماط) و**MIGRATION.md:75** و**review-protocol.md / review-automation.md** (سجلّا مراجعة مجمّدان — «تصحيحهما» = تزوير سجل الأدلة). الفحص الفعلي: 8 ملفات mطابقة.
- **الأثر:** بوابة مرحلة التأسيس إمّا محجوبة أبدياً أو تُجتاز بتحرير وثيقة القرار وسجلات المراجعة — كلاهما خرق لعقيدة الأدلة.
- **العلاج:** حصر الـ grep بالوثائق الست المصمِّمة (PRD/ARCHITECTURE/BRAIN/PROTOCOL/AUTOMATION/PROJECT-STRUCTURE) واستثناء الخطة/المراجعات/التقارير صراحة، أو فحص السياقات الإلزامية فقط (أسطر cron/paths التقريرية).

### 🟡 MEDIUM

**M1 — اختبار fail-loud السلبي في Phase 3 يناقض تصميم 3.4 نفسه**
- `MASTER-PLAN.md:174`: نزع `SHAMEL_HOME` ثم توقّع exit ≠ 0. لكن 3.4 (سطر 158) يعرّف سلّماً بـ **fallback** إلى `~/Desktop/SHAMEL/...` — وهذا المسار **سيكون موجوداً** وقت التنفيذ (أنشأته Phase 2.2). النتيجة الفعلية: exit 0 عبر الـ fallback → الاختبار يفشل دوماً، أو يُلوى `paths.py` ليرمي عند غياب env فيُكسر التصميم.
- **العلاج:** الاختبار السلبي يوجّه الـ fallback لمسار معدوم (`SHAMEL_HOME=/nonexistent`) بدل نزع المتغير.

**M2 — معيار Phase 10 على مسار معدوم + إسكات صامت (خرق P10 حرفياً)**
- `MASTER-PLAN.md:430`: `du -sh ~/Desktop/Lorka/MAIN/.opencode 2>/dev/null` — المسار غير موجود (تحقق حي)، و`2>/dev/null` يجعل الفحص يمرّ فارغاً بصمت. الخطة التي مبدأها «فشل صاخب» (P10) تزرع فحص دفنٍ يمرّ زوراً.
- **العلاج:** المسار الحقيقي `~/Desktop/Lorka/.opencode` + مقارنة رقمية آلية (`du -sb … | awk` ضد عتبة) بلا إسكات stderr.

**M3 — تناقض «remote أو mirror» مع قبولٍ يفترض GitHub حصراً**
- Phase 0.1 (سطر 49) يجيز «remote خارجي **أو** mirror محلي bare»، وPhase 7 يجيز `(pending)` (سطر 307/`PROTOCOL` D1)؛ بينما قبول Phase 8 (سطر 363) `gh run list -R <sakk-remote> … success` وPhase 8.7/11.1 «GitHub Actions» — مسار الـ mirror-only المسموح به يجعل معايير 8/11 **غير قابلة للتنفيذ**. تبعية خارجية (حساب GitHub + Actions runners) غير معلنة في أي سجل مخاطر.
- **العلاج:** إعلان GitHub remote شرطاً صلباً منذ 0.1 (وحذف بديل الـ mirror-only)، أو معيار CI بديل محلي (act/سكربت) لمسار الـ mirror.

**M4 — قبول Phase 5 يساوي عدّاداً حيّاً بثابت اليوم**
- `MASTER-PLAN.md:249` (وBRAIN:368): `COUNT(*) … = 47`. الملف `MAIN/.claude/memory/sessions.jsonl` **ينمو مع كل جلسة** (hook الـ Stop يلحق سطراً) — بين اليوم وتنفيذ Phase 5 (بعد 0–4 بجهد M/L) سيتجاوز 47، فالمساواة تفشل أو — أسوأ — تُفهم «استورد 47 فقط» فتُسقط جلسات حقيقية.
- **العلاج:** `عدد الصفوف المستوردة = wc -l للملف لحظة الاستيراد` (بصمة قبل/بعد)، لا ثابت مخبوز.

**M5 — عقدة cron: ADR-006(د) vs Phase 9.1 vs معيار القبول**
- ADR-006(د) (سطر 117): «يعملان عليه **لا على cron.d منفصل**». Phase 9.1 (سطر 380) يجيز «sed-merge **أو `/etc/cron.d/shamel`**» (وAUTOMATION:111 يسمّيه بديلاً مكافئاً). ومعيار القبول (سطر 392) `crontab -l | sed …` **لا يرى مسار cron.d أصلاً** — إن اختير البديل المجاز، الفحص يفشل زوراً.
- **العلاج:** حسم آلية تركيب واحدة في ADR-006(د) نصاً، وجعل `shamel automation status` هو الفاحص الوحيد أياً كانت الآلية.

**M6 — تناقض عقائدي موروث حول فروع `prj/*` لم يُحسم**
- G-02 (سطر 462، وريث PRD:82): سلامة SHAMEL = «main + **prj/\*** قصيرة فقط». بينما MIGRATION §8 (سطر 152): «**يُلغى نهائياً** نمط فرع `prj/<ID>` في ريبو الإطار». الوثيقتان الشقيقتان تشرّعان وتُلغيان النمط ذاته دون تعريفٍ فاصل (ما الذي يحمله فرع prj/ في إطارٍ مشاريعه ريبوهات مستقلة؟).
- **العلاج:** سطر تعريف واحد (مثلاً: فروع prj/ في SHAMEL = تعديلات إطارية باسم مشروع، لا كود مشروع) أو حذف prj/ من G-02.

**M7 — 104/105 pass موروثة vs قبول يشترط 100% بلا بند إصلاح**

## 4) ما يُحسب للوثيقتين (إنصاف الدحض)
- صفر مراجع ميتة في الإسناد (كل FR/G/RSK/ADR موجود في مصدره) — نادر في وثائق بهذا الحجم.
